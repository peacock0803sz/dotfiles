# 表記の規律

技術図は読み手が一瞬で文法を掴めることが肝心だ。凝った見た目より、規則が一貫していることの方が効く。

## 記号の意味を固定する

一つの図(と同じ文書に載る図のセット)の中では、視覚変数ごとに担う意味を一つに決める。

| 視覚変数 | 担う意味 | 例 |
|---|---|---|
| 形 | 要素の種別 | 角丸=サービス、円柱=DB、横円柱=キュー、人型=アクター、破線枠=外部システム |
| 塗り色 | 所属(チーム、自社/他社、レイヤ) | 自チーム=青、他チーム=灰、外部=白地に破線 |
| 枠線(グループ) | 境界の種類 | 破線=論理/信頼境界、実線太=デプロイ単位(ホスト、クラスタ、デバイス) |
| 線種 | 通信方式 | 実線=同期呼び出し、破線=非同期メッセージ、点線=データの流れ・レプリケーション |
| 矢印の向き | 呼び出しの向き(= 依存の向き) | 応答は描かない。シーケンス図では破線の戻り矢印で描く |

- 同じ色に二つの意味(「DB だから緑」と「チームAだから緑」)を持たせない
- 色だけで区別させない。形や線種と組み合わせ、白黒印刷や色覚多様性でも読めるようにする
- 既定パレット(draw.io 系の淡色): 青 `#dae8fc/#6c8ebf`、緑 `#d5e8d4/#82b366`、黄 `#fff2cc/#d6b656`、橙 `#ffe6cc/#d79b00`、紫 `#e1d5e7/#9673a6`、赤 `#f8cecc/#b85450`、灰 `#f5f5f5/#666666`。塗りは淡く、文字は黒系にする

## ラベル

- ノード: 1行目に名前、2行目に括弧で技術(`Order API` / `(Go, gRPC)`)。責務が名前から読めなければ、3行目に短い説明を入れる
- エッジ: 何を、どのプロトコルで。`HTTPS/JSON`、`gRPC GetUser`、`publish OrderPlaced`、`SQL (read)`。「データ」「通信」のような情報のないラベルなら、無い方がましだ
- 手順やメッセージに番号を振るときは、丸数字(①②…)を使わず `1.` や `(1)` と書く。丸数字は環境によってフォントに無く豆腐になりやすく、⑳より先は表せず、途中で番号を足すと振り直しになる
- 略語は図の中か凡例で一度は展開する(社内用語や独自略語は特に)
- 本文の文字は 12px 相当以上にする。縮小して貼られることを見越す

## レイアウト

- 主な流れ(ユーザー → 入口 → 内部 → データストア)を左→右に置く。縦長の媒体(スマホ、A4縦)向けなら上→下にする
- 外部アクターは左端、外部システムは右端か下端に寄せる
- 交差は最小限にする。交差が減らなければ、ノードの並び順か所属グループを見直す
- 入れ子は3段までにする(例: クラウド > VPC > サブネット)。4段目が要るなら図を分ける
- 同じ種類のノードが多数並ぶ(ワーカー×10 など)なら、1つのノードに「×N」と書くか、重ねた表現(D2 なら `style.multiple: true`)にする

## タイトルと凡例

- タイトルは「何の」「どの観点の」図かを書く。`注文システム コンテナ図`、`ログイン処理のシーケンス(正常系)`
- 凡例は、記号が2種類以上あって意味が自明でないときに付ける。使っていない記号は載せない
- 図の時点(日付やコミット)が重要なら、タイトル下か隅に小さく入れる。コードから起こした図は陳腐化するので、特に入れた方がよい

## 図の種類ごとの注意

### C4

- コンテキスト図: システムを1つの箱として描き、周りの人と外部システムだけを置く。内部は描かない
- コンテナ図: 独立してデプロイ/実行される単位(Web アプリ、API、ワーカー、DB、キュー、モバイルアプリ、組込みファームウェア)を描く。ライブラリやクラスは描かない
- コンポーネント図: 1つのコンテナの内部のモジュールやレイヤを描く。対象コンテナの外にあるものは、境界の外に最小限だけ置く
- 抽象度の違う要素(サービスとクラス)を同じ図に混ぜない

### シーケンス図

- アクターは呼び出しが始まる側から左に並べる
- 正常系を1枚描き、異常系は alt 枠を足すか別の図にする。分岐が3つを超えたら別図にする
- 非同期処理(キューに積んで後で処理する)は、同期の応答と区別できるように描く

### データフロー図

- ノードはデータを変換する処理とデータの溜まり場(ストア)の2種類にする。エッジはデータそのものなので、ラベルにはデータ名(`注文イベント`、`日次集計 CSV`)を書く
- PII や機密データが通る経路は色か太線で目立たせると、レビューに役立つ

### デプロイ/ネットワーク図

- グループは物理/論理の配置(リージョン、VPC、サブネット、k8s namespace、ホスト、デバイス)を表す
- エッジにはポートとプロトコルを書く(`443/TCP`、`MQTT 8883`、`BLE`)
- ファイアウォール、ロードバランサ、NAT など境界を越える箇所の要素は省略しない
- 組込み/IoT: デバイス内のプロセスやMCU/SoCの区別、無線/有線、ゲートウェイ経由かどうかを明示する
